# Reproducing the results

Everything in the paper is regenerated by the scripts below. No author names appear in the code.

## Environment

- Python 3.12 with `numpy`, `matplotlib`, `Pillow`, `pqcrypto` (ML-KEM-768 and ML-DSA-65).
  Pin `fonttools==4.51.0`: newer builds fail to load the compiled `iup` extension in this runtime,
  which breaks the PDF backend of matplotlib.
- ProVerif 2.05.
- TeX Live 2025 (`pdflatex`, `latexmk`, `pdftotext`).
- Tested on Windows 11, single core.

If ProVerif is blocked by an application-control policy, run `proverif/enroll.pv` and
`proverif/enroll_compromised.pv` on a machine where it is allowed; the two `RESULT` lines are recorded in
`proverif/README.md`.

`pip install numpy matplotlib pillow pqcrypto` is enough for the Python side. If `pqcrypto` is absent,
`enroll.py` falls back to X25519 + a toy RSA and says so in its output; the paper's numbers assume the
`pqcrypto` backend.

## One pass

```
cd prototype
python veil_core.py        # self-test; prints 9760 / 9824 / 10896 and extraction results
python eval_full.py        # E1-E5 -> results/full.json
python probe_vs_t.py       # probe vs box width -> results/probe_vs_t.json
python cost_model.py       # per-operation costs and the predicted total
python dual_regev.py       # real CPA dual Regev; ciphertext 3075 B
python td_demo.py          # MP12 trapdoor; carrier 8426 B, 384/384 bits recovered
python cca_demo.py         # FO rejects the anamorphic ciphertext
python enroll.py           # ML-KEM-768 + ML-DSA-65 enrollment
python mcp_demo.py         # gateway / credential / direct topologies

cd ../c
python gen_constants.py    # constants.h for the C kernel
gcc -O3 -shared -o "$TEMP/veil_kernels.dll" veil_kernels.c   # or into c/
cd ../prototype
python c_kernels.py        # equality checks + C-vs-NumPy benchmark

# end-to-end C signer (regular and attributable modes, extract and link)
cd ../c
gcc -O3 -shared -static-libgcc -o "$TEMP/veil_sign.dll" veil_sign.c -I . -L "$MINGW/lib" -lcrypto
strip "$TEMP/veil_sign.dll"   # required here: the unstripped build is blocked by the app-control policy
# copy libcrypto-3-x64.dll next to it in %TEMP%
cd ../prototype
python c_sign.py --reps 60    # self-test (incl. Merkle vs Python) + timings -> results/c_sign.json
python bench_py.py            # Python reference timings -> results/py_bench.json

If even the stripped DLL is refused with `WinError 4551`, the host's application-control
policy is blocking newly built binaries; use WSL instead (below).

# WSL / Linux, no app-control policy and no DLL search issues
#   sudo apt install build-essential libssl-dev python3
cd /mnt/d/Projects/"Anamorphic Ring Signature"
gcc -O3 -shared -fPIC -o /tmp/veil_sign.so c/veil_sign.c -I c -lcrypto
python3 prototype/c_sign.py --reps 100

cd ../proverif
proverif enroll.pv            # payload secrecy true, correspondence true
proverif enroll_compromised.pv  # payload secrecy false (negative control)

cd ../figures
python plot_results.py     # size, chi-square and probe figures (PNG + PDF)
python plot_c.py           # Fig. 3 (C-vs-Python cost) and Fig. 6 (detector AUC)
python plot_anon.py        # Fig. 7 (mask rejection and signer probe)
python make_figures.py     # draw.io sketches; the paper uses sm.png (Fig. 1) and figures/flow-two-panel.pdf (Fig. 2)

cd ..
latexmk -pdf veil.tex
```

## Stand-ins and caveats

- The ring prototype appends a **1088-byte structural stand-in** for the anonymous carrier; the 12835-byte
  figure is the ring plus the separately measured 3075-byte ciphertext. `results/phase3.json` records 10896
  for the stand-in.
- `td_demo.py` uses `n=384`, `q=2^13` for mechanics; the factor 13.5 is in coefficients and 7.3 in bytes.
- `cca_demo.py` uses `n=256, m=1024, t=256`; it demonstrates rejection, not a security level.
- `mcp_demo.py` simulates the transport and the tool latency (120 ms per step); no language model is called.
- Parameters are mechanics-only; the paper makes no security-level claim. The ring layer uses `d=256, k=3, l=4`: with `k >= l` the public key would determine the secret by linear algebra, so `k < l` is required.

## Lattice estimator

The MSIS figures come from the `lattice-estimator` on top of SageMath:

```
# install once (no root needed): Miniforge -> conda-forge Sage
bash _install_sage.sh            # or: mamba install -y sage
curl -L -o le.tar.gz https://codeload.github.com/malb/lattice-estimator/tar.gz/refs/heads/main
tar xzf le.tar.gz && mv lattice-estimator-main ~/lattice-estimator
~/miniforge3/bin/sage -c "import sys; sys.path.insert(0, '$HOME/lattice-estimator'); print('ok')"
```

`estimator/est_sis3.py` sweeps `k = 1..4` at `t = 19` and `t = 18..21` at `k = 3`, using the infinity-norm bound `2^t` given by the acceptance test `z in B`. `estimator/calib.py` runs the same estimator on `Dilithium2_MSIS_WkUnf` as a calibration point.
